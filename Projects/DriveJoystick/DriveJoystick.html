Objective


To eliminate the “boxing effect” caused by the circular joystick that limits the turning capabilities of the robot but not compromise sensitivity and control. A regular XY joystick as found on the VEX controller, with the following code allows for two wheeled robot to move freely:

$$ motor_L=(joy_Y-joy_X) $$

$$ motor_R=(joy_Y+joy_X) $$

This program maps the x and y coordinates of the joystick into a “box”. However, this creates a problem because the joystick is a circle. There will be parts of the box that the circle can't reach, and the robot isn't using its full power capability. The image below better illustrates this:



By taking the area of the circle and subtracting it from the area of the square, we get a figure of how much power isn't being used:

$$ ((2)(2))-(3.14(1^2)) $$

$$ = 4 - 3.14 $$

$$ = 0.86 $$

$$ (0.86/4)(100\%) = 22% $$

A simple solution would be to divide the resulting motor power by 2, effectively shrinking the box. But we run into another problem, the top parts of the circle will “max out” the motor power, as shown below:



This is a simple solution to the problem above, but makes the joystick super sensitive, and there's lots of unused space where the values of the motors will be stuck at 127!



Solution


In quadrant 1 of the joystick, we can either go straight or turn right. Therefore, the right motor is the only one we have to worry about modifying. The left motor's value is simply the hypotenuse of the right triangle created by the x and y components of the joystick (using pythagorean theorem). Firstly, I created a table of values relating the x value of the joystick to the right motor power. By experimentation, I found that the joystick values range between -127 and 127, with the 0 value being the neutral position:


Angle in Standard Position $$ joy_X $$ $$ joy_Y $$ $$ motor_R $$
90° 0 127 127
45° 90 90 0
0° 127 0 -127

Using these values, I created an equation for a quadratic that connects with these points:

$$ motor_R = 127 - 0.0158joy_X^2 $$

Using this knowledge, we can write an equation to model the relationship between the motors and the joystick:

$$ motor_L = sqrt(joy_X^2 + joy_Y^2) $$

$$ motor_R = sqrt(joy_X^2 + joy_Y^2) - 0.0158joy_X^2 $$

Note that we replaced 127 in the previous equation with the hypotenuse, so that we can control the speed of both motors. Creating code based on these two equations only partially solves our problems. When the hypotenuse equals 127, everything works as expected, but as the hypotenuse approaches zero, the robot starts “jumping around” when the joystick crosses the x axis. I realized that the “a” value of the quadratic equation above changes with varying hypotenuse lengths. I had to make a new equation relating the a value of the quadratic to the hypotenuse length. I did this by calculating the a values using a bunch of different hypotenuse lengths, and putting those results in a new table:


$$ joy_X $$ $$ motor_R $$
0 45
45 0
64 -64

$$ motor_R = hyp - 0.0316joy_X^2 $$

$$ joy_X $$ $$ motor_R $$
0 10
7 0
10 -10

$$ motor_R = hyp - 0.2007joy_X^2 $$

hyp a value
0 0.0158
7 0.0316
10 0.2007

$$ a = \frac{(0.0158)(127)}{hyp} $$

Which simplifies to:

$$ a = \frac{2}{hyp} $$

Now, using these equations combined, we should have a working drive motor code!

$$ a = \frac{(0.0158)(127)}{hyp} $$

$$ a = \frac{2}{hyp} $$

$$ motor_L = hyp $$

$$ motor_R = hyp - ajoy_X^2 $$

Now we can write the full final drive code using all four quadrants (since all that needs to be modified is the sign of the x and y components, and which motors are affected):

Conclusion


By using this code, we can get 22 % more power out of the robot's motors. This gives us an advantage and we're more able to push others around the court.
